# 小鹅通专栏批量下载设计

## 目标

用户在已登录的小鹅通专栏目录页点击扩展，扩展识别所有可访问课程，展示有序列表；用户只选择一次保存目录，随后扩展自动解析、下载并按目录标题命名全部选中课程。任务支持有限并发、失败重试、已下载跳过和页面重开后的恢复。

首个批量版本继续保持为独立扩展，只修改 `xiaoe-course-downloader/`。现有飞书插件、油猴和猫抓不在变更范围内。

## 非目标

- 不支持任意网站或任意课程平台。
- 不绕过登录、课程权限或 DRM。
- 不以 20 路并发为目标；第一版批量阶段固定最多 2 个课程任务并发。
- 不实现复杂的优先级、带宽调度或跨设备同步。
- 不保证合并带独立音轨和视频轨的 HLS；继续沿用单节版已经支持的直链媒体和简单、未加密 HLS VOD 边界。

## 方案选择

采用“小鹅通平台适配器 + 后台标签页兜底”的混合方案。

纯界面自动点击过度依赖 DOM、播放器和自动播放策略；纯内部 API 速度快，但任何接口变化都会阻断全部功能。混合方案优先使用小鹅通页面的结构化状态、专栏目录和已确认的接口模式，无法直接得到媒体地址时才加载受控后台标签页，通过现有 DOM/Resource Timing/网络候选捕获链路解析。

## 用户流程

1. 用户打开小鹅通专栏目录页并点击扩展。
2. 扩展显示“识别整个专栏”，只读提取目录。
3. 独立任务页展示专栏名称、课程总数、第一项、最后一项和完整课程列表。默认勾选全部可访问课程，锁定或缺少链接的课程显示为不可选。
4. 用户可以取消个别课程，然后选择一次目标目录并开始。
5. 系统从“尚未完成且没有冲突”的选中课程中取最前面的最多 3 项串行下载作为自动校准；这些项目全部成功后自动切换为最多 2 个课程任务并发，无需再次确认。选中不足 3 项时校准全部；所有项目都已由完成清单验证时直接结束，不进行空校准。
6. 如果校准项中任何一项失败，系统停止扩展队列，保留错误与已完成结果，避免对整个专栏重复制造失败请求。用户解决问题后点击“重试失败项”。
7. 任务页持续显示总数、等待、解析中、下载中、成功、跳过和失败数量，以及每节课程的具体状态。

## 核心组件

### 1. 小鹅通目录适配器

输入当前专栏页面，输出规范化目录：

```text
CourseCatalog {
  courseId,
  title,
  lessons: [{ lessonId, index, title, pageUrl, accessible }]
}
```

适配器按以下优先级读取：

1. 页面中可复用的结构化状态或小鹅通目录接口结果。
2. 专栏目录 DOM 中的课程链接、序号和标题。

目录必须满足：序号稳定、标题非空、URL 可解析、同一课程不重复。任务页在开始前显示数量与首尾项，让用户发现漏集、逆序或标题错误。目录识别阶段不下载媒体。

目录适配器必须处理分页和懒加载：

- 优先读取页面声明的课程总数和分页游标，持续请求下一页直到游标为空或已收集数量等于声明总数。
- DOM 模式持续滚动实际课程列表容器，等待新增课程；只有同时满足“出现底部/没有更多标志”和“连续 3 个加载周期没有新增唯一 lessonId/URL”才结束。
- 页面有声明总数时，规范化去重后的数量必须完全相等，否则目录识别失败并禁止开始。
- 页面没有声明总数时，必须到达明确的底部标志；否则标记为“目录数量未验证”并禁止开始。

“结构化状态或接口”不是对未知接口的假设。实施阶段必须先从用户当前可访问的真实专栏采集一份脱敏 fixture，确认接口 URL/方法、必要请求上下文、分页字段和响应结构，并为该结构编写适配测试后才能启用 API 路径。`webRequest` 只提供请求 URL、标签页和响应头等元数据，不能读取响应正文，不作为目录数据源。

### 2. 课程媒体解析器

媒体地址只在课程即将下载时解析，避免有时效的签名 URL 提前失效。

解析优先级：

1. 小鹅通适配器从该课程的结构化数据或已确认媒体接口获取直链/M3U8。
2. 创建或复用一个受控后台课程标签页，等待页面扫描和 `webRequest` 捕获媒体候选。
3. 两条路径均失败时记录具体原因，不要求用户逐集点击播放。

持久任务数据不保存媒体签名 URL。地址只在当前解析/下载生命周期内存活；遇到 401/403 时重新解析一次，再进入普通重试。

API 路径同样需要在实施阶段用当前小鹅通课程的脱敏请求 fixture 验证请求方法、必要上下文和媒体字段。后台标签页只作为全自动兜底，不能把人工点击播放作为成功条件：

- 队列为每个解析任务创建 `tabId + navigationEpoch + lessonId` 关联，顶层导航时清空旧候选。
- 页面加载完成后注入扫描器读取 DOM、Resource Timing 和已验证的小鹅通页面状态；只接受当前导航开始之后、当前 tabId 捕获的媒体候选。
- 候选按播放列表/直接媒体、MIME、URL 和捕获时间消歧，拒绝上一课程残留和单独的 HLS 分片。
- 15 秒内没有得到唯一候选即自动失败并关闭/回收标签页，不等待用户操作。
- 如果当前课程必须依赖真实用户播放手势才能产生媒体地址，则批量媒体适配器尚未达到验收标准；应继续完善平台接口解析，而不是要求用户逐集播放。

### 3. 可恢复批量队列

每个课程任务使用以下状态：

```text
pending -> resolving -> downloading -> committing -> success
                   \-> retry_wait -> pending
                   \-> failed
pending -> skipped
pending -> conflict -> pending（用户明确选择覆盖后）
```

- 从未完成、无冲突的任务中选取最多前三项固定串行，用作真实站点校准；完成清单验证的 `skipped` 不需要再次下载，也不计入校准样本。
- 校准通过后最多 2 个课程任务并发；每个任务把“解析 + 下载”作为一个单元，保证媒体地址即时使用。
- 普通网络失败最多自动重试 2 次，使用短退避；权限、DRM、明确不支持的 HLS 直接失败，不做无意义重试。
- 用户可以停止新任务派发；正在写入的单个文件完成后队列停止。
- 任务结束后提供“重试失败项”，不重新下载成功项。

队列调度运行在可见、持久的 `batch-runner.html` 扩展标签页中，不依赖可能随时终止的 MV3 Service Worker。Service Worker 只负责网络候选捕获和消息转发。

同一个任务通过 `navigator.locks` 获取 `xiaoe-batch:<jobId>` 独占锁；第二个任务页只能查看并跳转到已有运行页，不能重复派发。任务目录、课程列表、状态、尝试次数和写入字节数保存在 `chrome.storage.local`。每次状态转换先持久化再开始副作用，并使用 attempt token 忽略已失效 worker 的回调。任务页意外关闭后，浏览器释放锁；重新打开时把 `resolving/downloading` 恢复为 `pending`，清除内存媒体地址并重新解析。签名媒体 URL 不进入持久存储。

### 4. 目标目录和文件策略

用户只调用一次 `showDirectoryPicker()`。目录句柄存入扩展自己的 IndexedDB；重新打开任务时重新检查 `queryPermission/requestPermission`，浏览器要求授权时由用户点击恢复。

文件名直接使用适配器规范化后的目录标题，例如：

```text
65. 体制内的思考.mp3
```

批量模式使用确定性文件名，并在目标目录维护一个隐藏的 `.xiaoe-batch-manifest.json` 完成清单，记录 courseId、lessonId、文件名、完成字节数、媒体类型、可播放性检查结果和完成时间：

- 同名文件不存在：创建并下载。
- 同名文件存在，且完成清单中 lessonId、文件名和实际文件大小全部匹配：标记为 `skipped`，不生成 `(2)` 副本。
- 同名文件为零字节且没有完成记录：作为崩溃残留删除后重新下载。
- 同名文件非空但没有匹配的完成记录：标记为 `conflict`，计入独立统计，默认不覆盖、不视为成功。任务页只提供“确认覆盖冲突项并重新下载”；用户确认后任务转为 `pending`。第一版不提供把未知文件直接标成完成或自动改名。
- 写入失败：中止 writable，并清理本次新建的文件；不写完成记录。
- 媒体字节写完后，先把任务持久化为 `committing`，记录 attempt token、目标文件名和期望字节数，再关闭媒体 writable。关闭成功后重新读取文件大小，并对浏览器可解码的 MP3/M4A/MP4/WebM/WAV/AAC 创建临时 object URL，等待 `loadedmetadata` 且确认 duration 大于零；检查失败则不写完成记录。
- 完成清单使用 `createWritable({ keepExistingData: false })` 写入完整新 JSON，只有 `close()` 后新版本才替换旧版本。任务在清单关闭成功后才转为 `success`。
- 如果页面在媒体关闭后、完成清单提交前崩溃，恢复流程检查 `committing` 中的期望字节数、实际文件大小和可播放性；全部匹配则补写完成清单，否则零字节文件删除，未知非零文件转为 `conflict`。每次清单写入失败都保留 `chrome.storage.local` 中的 `committing` 记录供恢复。

这与单节模式当前的 `(2)` 防覆盖策略不同；批量模式需要可重复执行和断点恢复，因此以跳过确定性文件为准。

## 错误处理

- 目录为空、目录重复、首尾课程异常：禁止开始并显示目录诊断。
- 课程锁定或无权访问：标记不可选/失败，不尝试绕过。
- 媒体无法识别：记录解析路径和最终原因，可单项重试。
- 401/403：刷新课程解析一次；仍失败则提示登录或 Referer/Authorization 限制。
- 每次普通重试、401/403 重试或任务恢复都丢弃旧媒体 URL，从课程标识重新解析，禁止复用可能过期的签名地址。
- HLS 加密、BYTERANGE、直播或独立轨：沿用明确的不支持错误，禁止生成损坏文件。
- 目录权限丢失：暂停派发，用户重新授权后继续。
- 标签页或扩展任务页关闭：任务状态保留；重新打开任务页后恢复未完成项。
- 冲突文件：停止该项并计入 `conflict`；只有用户明确确认覆盖后才重新派发。

## 测试和上线顺序

### 自动测试

- 目录适配器 fixture：顺序、去重、锁定项、缺失标题/链接和 65–67 等实际编号。
- 文件命名：保留目录中的真实编号，禁止重复添加 `001-`。
- 队列状态机：并发上限 2、最多三项校准、全量已完成的空校准、失败退避、最多两次重试、停止与恢复。
- 单实例与恢复：任务页锁、重复任务页、attempt token、运行中状态恢复后重新派发。
- 文件策略：完成清单匹配后跳过、零字节重下、未知非空文件冲突、明确覆盖、失败清理、`committing` 崩溃窗口恢复。
- 完成验证：逐项检查完成清单、实际文件名、实际大小；浏览器支持的媒体格式逐项完成 metadata/duration 可播放性检查。
- 时效策略：媒体地址在任务开始时解析，不进入 `storage.local`。
- 后台标签页：导航 epoch 隔离、候选消歧、15 秒超时和自动关闭，全流程不需要用户逐集播放。

### 真实课程验收

1. 只读识别整个专栏，用户核对总数、第一项和最后一项。
2. 选择临时目录，自动串行下载前三项，检查名称、大小和可播放性。
3. 前三项全部通过后自动继续全专栏，最多并发 2。
4. 人为关闭并重开任务页，验证单实例恢复、媒体重新解析和完成清单匹配后的文件跳过。
5. 检查最终成功、跳过、失败和冲突数量之和等于选中课程数量；验收通过要求失败数和冲突数都为零。
6. 自动逐项核对完成清单、文件存在和实际大小；对浏览器支持解码的格式逐项确认 metadata/duration，有特殊容器时抽查第一项、中间项和最后一项的本机播放。

## 成功标准

- 用户从专栏目录页开始，只选择一次目标目录，不再逐集点击识别或下载。
- 所有可访问、受支持的课程按照目录中的真实序号和标题保存到同一目录。
- 任务进度可见，单项失败不会破坏其他文件，失败项可以重试。
- 默认并发不超过 2，任务可重复运行且不会生成重复副本。
- 最终选中课程全部为 `success` 或由完成清单验证的 `skipped`；`failed` 和 `conflict` 必须为零，才显示“专栏下载完成”。
